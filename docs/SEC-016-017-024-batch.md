# Security batch — SEC-016, SEC-017 and SEC-024

**Status:** Prepared on a staging branch; not deployed, not cleared for production. Focused CI and owner verification are pending. The approved initial SEC-016 PR remains unmerged until this batch is reviewed and tested.

## Scope

1. **SEC-016**: Prevent server Geocoding / legacy Maps keys from appearing in Admin Attendance or employee geofence JSON. The dedicated public Maps JS browser key is served to authenticated Admin, Employee, HR and Manager sessions, not anonymous/Candidate sessions. Existing dev key is configured in Render, but updated code has not deployed.
2. **SEC-017**: Earlier SEC-001 remediation replaced browser Supabase Storage SDK with an HRMS authenticated PHP Storage adapter, with server role/ownership checks, path rules, file-size and MIME signature verification, and no-upsert storage writes. This batch ensures rejected file content receives HTTP 415 **before** the backend attempts to inspect storage service credentials. The isolated regression tests exercise unauthenticated uploads, traversal, unknown buckets, fake HTML/PDF, SVG/JPEG and a valid fixture without storage access.
3. **SEC-024**: Disable Slim's detailed exception output in **every** environment; exceptions are handled and server-side logging remains enabled. Do not rely on APP_ENV=development to display sensitive traces to development users. The source test also verifies generic auth errors and no raw PDO echo.

## Cost and Android release safeguard

This batch changes .github/workflows/sec006.yml so security PRs still run Android **static checks**, but native APK compile/upload is **skipped** on automatic pull requests and pushes. Only a later manually dispatched, owner-authorized final workflow with build_final_apk=true may compile an APK, and only dispatch on main can publish it. This meets the owner instruction: no APK building until remaining security issues are resolved.

## CI and verification

- Check PHP syntax on revised backend routes.
- Run existing SEC-001 storage validation and SEC-016 policy/source regression.
- Run new SEC-017 browser-adapter and isolated API HTTP tests, using synthetic PostgreSQL and no Supabase service key.
- Run SEC-024 exception-response source checks.
- Run SEC-016 authenticated Maps API role/key regression.
- Run Vite frontend production build.
- Check workflow job result (Android native build must be skipped), then owner test Admin, Employee, HR and Manager Maps and representative uploads in the DEV application.

These tests do **not** exercise actual Supabase Storage or production secrets. Do not merge or deploy without review, green tests, and the relevant development smoke tests. Other security issues (including SEC-018 and later) remain separate. Retire legacy Maps key only after SEC-016 live validation.
